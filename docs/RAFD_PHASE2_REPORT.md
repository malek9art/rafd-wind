# RAFD Desktop — تقرير المرحلة 2

## الحالة

- **المرحلة:** 2 — إصلاح سلامة المبيعات والمخزون
- **الحالة:** مكتملة محليًا
- **النطاق:** المبيعات، المخزون المرتبط بالبيع، إلغاء الفواتير، تكلفة البيع التاريخية
- **المراحل غير المشمولة:** دورة المشتريات الكاملة، الصلاحيات، الطباعة، النسخ الاحتياطي، ZATCA

## التغييرات الأساسية

### سلامة إنشاء البيع

- منع تكرار المنتج داخل الفاتورة.
- منع بيع المنتج المعطّل.
- التحقق من أن الكميات والمبالغ أرقام finite وغير سالبة.
- التحقق من السعر والتكلفة الحاليين قبل تسجيل البيع.
- منع تجاوز المخزون حتى داخل عملية الخصم.
- منع إرسال وزن لمنتج غير موزون.
- إلزام الوزن الموجب للمنتجات الموزونة.
- التحقق من اتساق علم البيع بالوزن مع تعريف المنتج.
- منع القيم السالبة أو غير finite في تكلفة المنتج والمخزون والحد الأدنى.

### الفواتير

- إضافة عداد SQLite مستقل لأرقام الفواتير.
- منع إعادة استخدام رقم فاتورة بعد إلغاء آخر فاتورة.
- حفظ `payment_method`.
- إضافة حالة الفاتورة وبيانات الإلغاء.
- منع الحذف الصلب.
- إضافة إلغاء محاسبي مع السبب والمستخدم والتاريخ.
- عكس المخزون عند الإلغاء.
- عكس إجمالي مشتريات العميل عند الإلغاء.
- عكس قيد البيع الآجل تلقائيًا فقط إذا لم توجد حركة لاحقة في دفتر العميل؛ الحالات غير الآمنة تُرفض بدل إسقاط أثر مالي بصمت.

### تكلفة البيع والتقارير

- إضافة `sale_items.unit_cost`.
- حفظ تكلفة المنتج وقت البيع.
- ترقية التقارير لاستخدام تكلفة البيع التاريخية.
- استبعاد الفواتير الملغاة من الإيراد وCOGS والإيراد اليومي.

### الواجهة

- شاشة POS تطلب المنتجات النشطة فقط.
- منع إدخال وزن صفري أو سالب من واجهة POS.

### قاعدة البيانات

- رفع `SCHEMA_VERSION_CODE` من 3 إلى 5.
- migration v4: طريقة الدفع، حالة الإلغاء، بيانات الإلغاء، عداد الفواتير.
- migration v5: لقطة تكلفة المنتج داخل بنود البيع.
- الحفاظ على ترقية قواعد المرحلة 0 والبيانات القديمة.

## الاختبارات المضافة أو المحدثة

تمت إضافة تغطية لـ:

- المنتج المكرر داخل الفاتورة.
- المنتج المعطّل.
- الوزن المفقود والصفر والسالب.
- إلغاء الفاتورة النقدية.
- إلغاء الفاتورة الآجلة الآمن.
- منع الإلغاء بعد حركة لاحقة في دفتر العميل.
- عكس إجمالي مشتريات العميل.
- عدم إعادة استخدام أرقام الفواتير.
- استبعاد الفواتير الملغاة من التقارير.
- استخدام التكلفة التاريخية في COGS.
- migrations v4/v5.
- تصنيف قناة إلغاء الفاتورة.

## ملاحظة مهمة

التعديل الحالي يحمي طبقة المبيعات حتى لو تم استدعاؤها مباشرة عبر IPC. لا تزال واجهة إلغاء الفاتورة نفسها غير مضافة إلى شاشات المستخدم، وستكون ضمن مرحلة الواجهات والصلاحيات.

كما أن نتيجة Windows/installer لم تُعتبر ناجحة بعد؛ يجب تشغيل CI على Windows بعد تثبيت هذه الدفعة.
