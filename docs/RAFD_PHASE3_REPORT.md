# RAFD Desktop — تقرير المرحلة 3

## الحالة

- **المرحلة:** 3 — إصلاح دورة المشتريات والاستلام
- **الحالة:** مكتملة محليًا
- **سياسة الدين المعتمدة:** حسب قيمة الكمية المستلمة فعليًا

## التغييرات الأساسية

### حالات المشتريات

تم اعتماد الحالات:

```text
draft
pending
partially_received
received
cancelled
```

وتم تحويل الحالة القديمة `completed` إلى `pending` عبر migration v6.

### الاستلام الجزئي

- الاستلام أصبح تراكميًا لكل بند.
- الكمية المستلمة في الطلب تمثل الكمية الإجمالية بعد العملية، وليست فرقًا جديدًا.
- يتم حساب الفرق بين الكمية السابقة والجديدة.
- المخزون يزيد بالفرق فقط.
- يمكن تنفيذ عدة عمليات استلام جزئي.
- لا يمكن تجاوز الكمية المطلوبة.
- لا يمكن إنقاص كمية مستلمة سابقًا.
- لا يمكن إعادة أمر `received` إلى حالة تسمح بإعادة الاستلام.

### دين المورد

- كل استلام يضيف قيمة الكمية المستلمة فقط.
- الدفعات اللاحقة تقلل رصيد المورد عبر قيد `payment`.
- الدفعات قبل أول استلام ممنوعة لتجنب خلط الدفعة المقدمة بالدين.
- يدعم النظام استلامًا جزئيًا، ثم دفعة، ثم استلامًا لاحقًا مع بقاء الرصيد صحيحًا.

### المخزون والتكلفة

- تحديث المخزون ذري داخل معاملة SQLite.
- تحديث تكلفة المنتج بمتوسط مرجح عند كل استلام جديد.
- تحديث بيانات التغليف عند وصول كمية جديدة.
- التحقق من المنتج قبل إنشاء أمر الشراء.
- حساب إجمالي بند الشراء مركزيًا من الكمية × تكلفة الوحدة.
- عدم الوثوق بإجمالي قادم من الواجهة.

### الحماية

- منع تغيير المورد بعد بدء الاستلام أو وجود حركة مالية.
- منع استبدال البنود بعد بدء الاستلام.
- منع حذف أمر بدأ استلامه أو عليه حركة مالية.
- منع إلغاء أمر بدأ استلامه دون مسار عكسي مستقل.
- تسجيل الإنشاء والاستلام والتعديل والدفع والحذف في سجل التدقيق.

### الواجهة

- دعم حالات الاستلام الجزئي في شاشة المشتريات.
- إرسال قائمة `received_items` صريحة بدل إعادة إرسال بيانات البند كاملة.
- عرض حالات `pending` و`partially_received` و`received` و`cancelled` بوضوح.
- منع زر الاستلام للأوامر الملغاة أو المكتملة.
- تحديث عرض حالة أوامر الموردين.

## الاختبارات

تمت إضافة تغطية لـ:

- استلام جزئي على مرحلتين.
- إضافة الفرق الجديد فقط إلى المخزون.
- المتوسط المرجح للتكلفة.
- الدين حسب قيمة المستلم.
- دفعة بعد الاستلام الجزئي.
- استلام لاحق بعد الدفعة.
- منع الاستلام الزائد.
- منع الدفعة قبل أول استلام.
- منع الاستبدال بعد بدء الاستلام.
- منع حذف الأمر المستلم.
- التعامل مع الحالة القديمة `completed`.
