# RAFD Desktop — تقرير المرحلة 6

## الحالة

- **المرحلة:** 6 — النسخ الاحتياطي والاستعادة والتحديثات
- **الحالة الحالية:** النسخ المحلي والاستعادة وتنسيق التشفير ومسار التحديث جاهزة؛ الرفع السحابي والتوقيع التجاري متبقيان
- **المزود المعتمد مبدئيًا:** Supabase Storage للنسخ، GitHub Releases للتحديثات
- **نموذج المفتاح:** عبارة مرور/مفتاح استرداد يملكه العميل

## مدير النسخ الاحتياطية

- إنشاء النسخة عبر `better-sqlite3.backup()` المتوافق مع WAL.
- حفظ ملف SQLite مستقل داخل `userData/backups`.
- إنشاء metadata بجانب كل نسخة.
- حفظ وقت الإنشاء وإصدار التطبيق وإصدار المخطط والحجم وSHA256.
- التحقق من checksum وSQLite `integrity_check`.
- رفض النسخ ذات المخطط الأحدث من التطبيق.
- منع استخدام مسارات عشوائية عند الحذف أو الاستعادة.

## الاستعادة

1. التحقق من النسخة.
2. إنشاء نسخة أمان من الحالة الحالية.
3. إغلاق قاعدة البيانات.
4. حذف ملفات WAL/SHM القديمة.
5. استبدال ملف SQLite.
6. إعادة تشغيل التطبيق لإعادة بناء المقبض والـIPC.

## تشفير النسخ

تمت إضافة تنسيق تشفير مستقل في `src/main/backup-crypto.ts`:

- AES-256-GCM.
- اشتقاق المفتاح عبر scrypt.
- salt وIV عشوائيان لكل نسخة.
- checksum للمحتوى الأصلي.
- رفض عبارة المرور القصيرة أو الخاطئة.
- كشف تلف المحتوى بعد التشفير.

لا يتم حفظ عبارة المرور أو المفتاح داخل التطبيق.

## التحديثات

تمت إضافة `electron-updater` مع:

- GitHub Releases في `electron-builder.yml`.
- فحص يدوي للتحديث.
- تنزيل يدوي بعد موافقة المدير.
- حالة التحديث والتقدم والأخطاء.
- إنشاء نسخة احتياطية قبل تثبيت التحديث.
- منع التثبيت قبل اكتمال التنزيل.
- التحديث يعمل فقط في النسخة المثبتة، وليس في وضع التطوير.

## الواجهة

تبويب النسخ الاحتياطية داخل شاشة الإدارة يتيح:

- إنشاء نسخة.
- فحص checksum وSQLite.
- استعادة للـAdmin.
- حذف للـAdmin.
- فحص حالة التحديث.
- تنزيل التحديث.
- تثبيت التحديث للـAdmin بعد إنشاء النسخة الاحتياطية.
